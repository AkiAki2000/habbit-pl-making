# habbit-pl-making — 外食チェーン株価・IR・決算KPIトラッカー

外食チェーン25社の株価を毎朝自動取得し、Webダッシュボードで株価推移・時価総額・IR（適時開示）履歴・決算KPIを確認できるプロジェクトです。株価に加えて、TDnet（適時開示情報閲覧サービス）を毎朝巡回してIRイベントと決算短信のKPI（売上高・営業利益・経常利益・純利益・EPS）を自動で蓄積していきます。

## 全体構成

```
docs/                    GitHub Pages で公開する静的ダッシュボード（このフォルダがそのままサイトになる）
  index.html / app.js / style.css
  companies.json         追跡銘柄マスタ（コード・銘柄名・ブランド・発行済株式数）
  data/prices/{code}.json  日次の終値・時価総額の履歴
  data/ir/{code}.json      IR（適時開示）イベントのログ（自動検知＋手動追記）
  data/kpi/{code}.json     決算短信のKPI履歴（売上高・営業利益・経常利益・純利益・EPS）
  data/status.json         直近の株価自動取得結果（成功・エラー）
scripts/
  fetch_prices.py         朝・夕方に実行：最新終値と（可能なら）発行済株式数を自動取得し記録
  backfill_prices.py      過去分をまとめて取得（デフォルト2026-01-01〜今日、価格のみ）
  fetch_ir.py             毎朝実行：TDnetを巡回し、追跡銘柄の適時開示を自動検知してIRログに追記
  fetch_earnings_kpi.py   毎朝実行：TDnetの決算短信XBRLから主要KPIを自動抽出してKPIログに追記
  add_ir_event.py         IRイベントを1件手動登録するCLI（自動検知で拾えなかったものの補完用）
  common.py               共通の読み書きヘルパー
.github/workflows/
  fetch-daily.yml          平日朝7:00・夕方16:30(JST)に自動実行：株価・時価総額を取得
  fetch-ir.yml             平日朝7:05(JST)に自動実行：直近5日分のIR開示を検知
  fetch-earnings-kpi.yml   平日朝7:10(JST)に自動実行：直近5日分の決算短信からKPIを抽出
  backfill.yml             手動実行（Actionsタブから）で株価の過去分バックフィル
```

## 使い方

### 1. GitHub Pages を有効化する

リポジトリの Settings → Pages で「Deploy from a branch」→ ブランチ: このブランチ（またはmainにマージ後）/ フォルダ: `/docs` を選択してください。有効化すると `https://<ユーザー名>.github.io/<リポジトリ名>/` でダッシュボードが見られます。

### 2. 株価の自動取得（朝・夕方）

`.github/workflows/fetch-daily.yml` が平日朝7:00と夕方16:30(JST)の2回自動実行され、`docs/data/` を更新して自動コミット・プッシュします。Pages は自動で再デプロイされます。

- 朝7:00の実行は市場が開く前なので、その時点で取得できるのは前営業日の終値です。
- 夕方16:30の実行は市場が閉まった後（取引終了15:00 JST）なので、その日の終値が当日中に反映されます。同じ日付のレコードは上書きされるだけなので、朝と夕方で重複は発生しません。

手動で今すぐ実行したい場合は GitHub の Actions タブ → 「株価取得（朝・夕方）」→ Run workflow。

### 3. 過去分のバックフィル（2026年1月〜）

Actions タブ → 「株価バックフィル（手動実行）」→ Run workflow。開始日はデフォルトで `2026-01-01` です。1社だけやり直したい場合は証券コードを指定してください。

データソースは Yahoo Finance の非公式チャートAPI（`yfinance` ライブラリ経由）です。このセッションのサンドボックス環境は外部ネットワークが制限されておりここでは実行・検証できませんでしたが、GitHub Actions のランナーは通常のインターネットアクセスを持つため、そちらで正常に動作するはずです。初回はバックフィルワークフローを実行してデータを埋めてください。

### 4. 発行済株式数（時価総額の計算に必要）

`fetch_prices.py` は毎朝 Yahoo Finance から発行済株式数の自動取得を試みます（`shares_outstanding_source: "auto (yfinance)"`）。日本株はこの値が取得できない・古いことがあるため、取れなかった銘柄は `docs/companies.json` の `shares_outstanding` を四半期決算短信や有価証券報告書の値で手動更新してください。

自動取得値が前回と変わった場合は「株式数変更」として自動的にIRログへ記録されるので、自社株買いや株式分割などの動きに気づきやすくなっています（実際の開示内容を確認してnoteを補完することを推奨）。

### 5. IR履歴の記録

```
python scripts/add_ir_event.py --code 3563 --date 2026-04-10 \
  --category 決算 --title "2026年2月期 通期決算を発表" \
  --url "https://www.foodlife.co.jp/ir/..." \
  --note "経常利益は前期比+8%"
```

category の例: 決算 / 業績修正 / 配当 / 株主優待 / 自己株式取得 / 株式分割 / M&A・提携 / その他適時開示

IR・決算KPIは `fetch-ir.yml` / `fetch-earnings-kpi.yml` が毎朝TDnetを巡回して自動で記録するため、通常は本コマンドを使う必要はありません。自動検知が拾えなかったIRや、TDnetの保存期間より前の開示を補完したい場合にのみ、実際の開示資料を確認しながら手動で追加してください（実在しない開示内容の自動生成は行わないでください）。

## ローカルで確認する

```
cd docs && python3 -m http.server 8000
```

`http://localhost:8000` を開くと、`docs/data/` にあるJSONをそのまま読み込んで表示します（初回・データ未取得時は「データがありません」と表示されます）。

## 既知の制約

- 株価データソース（Yahoo Financeの非公式API）は仕様変更で取得できなくなる可能性があります。`docs/data/status.json` にエラーが記録されるので、ダッシュボード上部の状態表示で気づけます。
- バックフィルした日付の時価総額は、その日時点の実際の発行済株式数ではなく現在値を使った概算です（`shares_estimated: true` で明示）。正確な推移が必要な場合は、IR履歴を参照しながら `docs/data/prices/{code}.json` を手動で補正してください。
- IR履歴・決算KPIはTDnet（適時開示情報閲覧サービス）を毎朝巡回して自動収集していますが、**TDnetの日次開示一覧ページは直近およそ5〜6週間分しか保持されません**（それより古い日付は404になります）。そのため株価データ（Yahoo Finance経由で2026年1月まで遡及取得済み）とは異なり、IR履歴・決算KPIを2026年1月まで遡ってバックフィルすることはできません。運用開始（2026年8月頃）以降のデータを日次で蓄積していく方針としています。過去分をどうしても補いたい場合は、EDINET（金融庁）や各社IRサイトの個別スクレイピングが選択肢になりますが、現時点では未実装です。
